## 技术类用户偏好

1. 更吃“真实经历 + 反差结论”，不吃上来就贴表格。  
   小红书爆款拆解反复强调真实性、个人化表达和真实场景；技术内容也需要先讲“我差点信了/我怎么查的”，再给数据。

2. 更愿意收藏可复用模板、清单和避坑指南。  
   涨粉复盘文把收藏率视为实用价值指标，提到模板/教程类内容更容易被收藏。S1 内容应给“以后看到神法怎么验”的 3-4 步，而不是只宣判失败。

3. 讨厌“广告感”和“爹味专业感”。  
   小红书用户对广告感敏感，金融类内容尤其要避免“老师/带单/收益承诺”。作者卡要把“不接金融广告、不卖荐股、不卖课”放在很显眼的位置，反而增加信任。

4. 技术/AI 内容也要有生活化入口。  
   AI/科技封面建议避免过强技术感，使用大字、关键数字、真实截图/图表。S1 应保留严谨图，但入口文案从“Gate1 Report”改成“我差点上当，跑完发现全段亏”。

5. 会被长段数字劝退。  
   封面和正文都要压缩信息密度。把 `1423 天`、`36 笔`、`19.4%`、`FAIL` 做成独立数字卡，每屏只让用户记住一个点。

## 封面规律

- 0.3-3 秒内传递核心信息：封面先让人知道“这条跟我有什么关系”。
- 大字 + 关键数字：`1423 天`、`36 笔`、`19.4%` 比整张表更适合移动端。
- 高对比色：小红书红 `#FF2442` + 白底 + 少量黄/黑强调，不做复杂渐变。
- 构图要简单：一屏一个主结论，不把 4 个表格挤在一起。
- 图表截图可作为信任材料，但不要当首屏唯一信息；先给故事和结论，再给原图。

## GitHub 链接风险评估

结论：可以放完整 GitHub URL，但要把它定位为“公开代码/数据来源”，不要写成交易转化链路。

实证与判断：

- 官方/媒体口径对“站外导流”的重点是交易、私域联系方式和站外成交。每日经济新闻报道小红书《社区商业公约》提到，商家不应在个人页、评论、私信把交易引导到站外，平台希望交易闭环在站内。https://www.nbd.com.cn/articles/2022-05-06/2266467.html
- 多个运营风控案例把高风险词集中在微信、二维码、加 V、私聊交易、报价单、进群领资料等。GitHub 不属于这些典型私域交易词，但仍是外站 URL。https://shangjiazhushou.com/article/23972839-2551
- 检索 `小红书 GitHub 链接` 未发现“GitHub 一放必违规”的可靠证据；反而能检索到不少小红书工具/CLI 项目把 GitHub 作为开源地址展示，例如 redbook CLI。https://github.com/lucasygu/redbook

建议写法：

- 推荐：`完整代码和数据在 GitHub：https://github.com/xiaoli-ai-factory/trade`
- 推荐：`评论“扒穿”，我把公开仓库路径贴给你`
- 避免：`私信我加群领资料`、`加 V 领代码`、`进群带你操作`
- 避免：把 GitHub 链接包装成付费资料、课程入口或荐股入口。

## 评论引导话术边界

合规边界：

- 可以引导站内评论讨论：`评论区打“扒穿”，我补公开仓库路径/复盘清单`
- 可以把补充材料放主页合集/置顶笔记/公开仓库。
- 不要用 `抽奖`、`送`、`私信领`、`微信`、`二维码`、`加 V`、`进群` 等高风险表达。
- 回复不要高频复制同一句话；新号尤其容易被算法误判。

参考来源：

- 评论/互动引导风险：关键词扫描、异常互动、用户举报会触发审核。https://www.518wcb.com/8536.html
- 站外导流改写示例：把微信/扫码/加群替换成站内私信、主页合集、置顶笔记。https://shangjiazhushou.com/article/23972839-2551
- 关键词自动回复要把合规、数据、转化压进同一条短回复，回复内容不能含外链/微信/违规断言。https://www-xiaohongshu.cn/blogs/1798149405/

## 金融/反诈内容红线

- 不荐股、不荐基、不预测未来价格，不暗示“买卖时机”。
- 不承诺收益，不出现“稳赚”“无风险”“日赚”“保本保息”等表达。
- 不用清华/工程师身份给投资结果背书，只能给“如何验证数据”的工程方法背书。
- 必须显眼写：`不接金融广告 / 不卖荐股 / 不卖速成致富课`。

## 对 S1 杨永兴反诈的具体调整

1. 标题从工程结论改成故事钩子：  
   `我差点信了杨永兴尾盘法，直到跑完 1423 天`

2. 首屏只放 4 个记忆点：  
   `1423 天`、`36 笔`、`19.4% 胜率`、`全段亏 / FAIL`

3. 正文用第一人称短句：  
   `我也想找捷径` -> `差点拿 1 万试` -> `先用 AI 跑了一遍` -> `结果全段亏`

4. 数据卡替代表格墙：  
   每个关键数字独立成卡，图表作为证据卡放后面。

5. CTA 只保留 GitHub + 全网同名 + 评论暗号：  
   `GitHub: https://github.com/xiaoli-ai-factory/trade`  
   `全网同名：小李的 AI 工厂`  
   `评论暗号：扒穿`

6. 作者卡要解决信任和风险：  
   `清华 / 芯片架构 CPU/GPU/图像/AI 芯片 / AI 工程师`  
   同屏显眼写死线：`不接金融广告 / 不卖荐股 / 不卖速成致富课`

7. 数据严谨保留但下沉：  
   把 `PIT、退市股、OOS、对照组` 放成“为什么能信”卡，不在首屏压用户。

8. 发布评论建议：  
   置顶评论：`完整代码和数据在公开 GitHub： https://github.com/xiaoli-ai-factory/trade 。想看我下一条扒哪个神法，评论“扒穿”。不是投资建议，不卖荐股。`
